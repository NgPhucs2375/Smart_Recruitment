# AGENTS.md — Smart_Recruitment

## Stack / layout
- .NET 10 Clean Architecture + Next.js 16 / React 19 monorepo in one folder.
- Backend entry: `src/WebApi/WebApp.Server/Program.cs`. Projects: `src/Domain`, `src/Application`, `src/Infrastructure/{Infrastructure.Identity,Infrastructure.Persistence,Infrastructure.Shared}`, `src/WebApi/WebApp.Server`.
- Frontend: `src/WebApi/frontend` (Next.js App Router, refine.dev + CopilotKit v1.70 + SignalR). Vercel builds only frontend (`vercel.json`: `npm install --legacy-peer-deps` — always use that flag here).

## Run
- Backend (from repo root): `dotnet run --project src/WebApi/WebApp.Server` — needs Postgres + Redis + RabbitMQ up first: `docker compose up -d postgres redis rabbitmq`.
- Full stack: `docker compose up --build` (ports: backend `${BACKEND_PORT:-5000}`→8080, frontend `${FRONTEND_PORT:-3000}`→3000, agent `${AGENT_PORT:-8000}`).
- Frontend dev: `cd src/WebApi/frontend && npm run dev` (port 3000 — the only origin in backend CORS `AllowFrontend`).
- Default seed login: `superadmin@gmail.com` / `123Pa$$word!` (see `README.md` + `Infrastructure.Identity/Seeds`).

## Env (non-obvious)
- Backend calls `DotNetEnv.Env.Load()` in `Program.cs` — it reads repo-root `.env`. Copy `.env.example` → `.env` first.
- `GROQ_API_KEY` is **required**: `AIAgentExtension.CreateSmartAgent` throws without it. Model is `qwen/qwen3.6-27b` via Groq (`WebApp.Server/Extensions/AIAgentExtension.cs`, `frontend/agent.ts` has a `specificationVersion` Proxy hack for CopilotKit — don't "fix" it).
- `appsettings.json` secrets (JWT, Mail, connection strings) are placeholders; real values come from env/user-secrets. `appsettings.Development.json` is gitignored.
- Frontend server proxy default is `DOTNET_API_URL=https://localhost:5001` (`lib/dotnet-proxy.ts`) — set it explicitly when backend runs elsewhere (e.g. `http://localhost:5000` under compose).

## Backend conventions
- Two EF Core Postgres contexts, **both auto-migrated + seeded on startup** by `Initializer/ApplicationInitializer.cs` (`Database.Migrate()`). Don't add manual migrate steps to dev flow.
- EF CLI commands must name the context: `dotnet ef migrations add <Name> --context ApplicationDbContext` (or `--context IdentityContext`); design-time factories read `WebApp.Server/appsettings.json`.
- Controllers inherit `Controllers/BaseApiController.cs`: versioned route `api/v{version}/[controller]`, MediatR via `Mediator`, auth via Casbin `Enforcer` (`wwwroot/model.conf` + `policy.csv`) with DB role-claim fallback in `EnforcePermissionAndExecute(resource, action)`. `policy.csv` is a regenerated cache (DB is truth) — don't hand-edit.
- `PropertyNamingPolicy = null` on JSON — backend returns PascalCase property names; keep frontend types matching.
- Endpoints: SignalR hub `/api/hubs/notifications`, AG-UI agent `/api/copilotkit` (CORS-restricted).

## Frontend notes
- `next.config.ts` has `typescript: { ignoreBuildErrors: true }` — type errors don't fail builds; run `npx tsc --noEmit` manually before claiming type-safety.
- Scripts are only `dev | build | start | lint` — no tests. Backend has no test projects either; verify with `dotnet build` + `next lint`/`next build`.
- `src/WebApi/frontend/AGENTS.md` is auto-generated by `next dev` — leave it alone.
- `Dockerfile` in `WebApp.Server` references a stale `WebApp.Client` path and won't build as-is; compose uses it for `backend` — prefer `dotnet run` locally over `docker build` of backend.
